# 做项目，顺便把内容做出来

**一句话**：别再另外找时间想选题：先把项目往前推，把遇到的问题、做过的选择和最后结果记下来，这些就是最真实的内容。

**问题**：我想持续做内容，又不想让创作抢走项目时间；但现在把项目和创作分开做，既累，写出来的东西还容易空。真正卡住我的不是选题太少，而是做项目时产生的问题、判断和结果，没有直接进入创作。

**解决方案**：把项目设成主线，内容只加工项目已经产生的东西：我负责记录真实判断，AI 只负责整理，读者反馈再决定下一次讲什么。

**逻辑**

1. 项目和创作分开运行，就要为两边分别找时间、找素材，创作很快会变成第二份工作。
2. 真正推进项目时，本来就会遇到问题、做出选择并得到结果，这些比凭空找来的选题更真实。
3. 只要及时记下“发生了什么、我怎么选、结果怎样”，一次经历就留下了可以加工的内容原料。
4. AI 可以帮忙整理表达，但不能替我编经历和观点；内容仍然来自我的行动和判断。
5. 内容发出去后的追问和反应，又会告诉我哪些问题值得继续研究和表达。

## 最小闭环：从一个项目问题做出一条内容

**起点**：一个本周正在推进的小项目。

1. 解决项目里一个真实问题，并写下“发生了什么、我怎么选、结果怎样” → 一条项目记录。
2. 从记录里挑出一个能帮到具体读者的问题，删掉无关背景 → 一条 150–300 字的内容草稿。
3. 把草稿发给三位目标读者或公开发布，收集他们的追问和反应 → 一份真实反馈。
4. 根据反馈写下“保留什么、改什么、下次回答什么” → 下一轮项目记录或选题的起点。

**闭环**：读者能看懂并提出追问，就沿着这个问题继续；没人理解或没有反应，就先改问题和表达，不增加更多生产步骤。

**完成**：已经发布或发送一条内容，记录至少一条反馈，并明确下一轮保留或修改什么。
