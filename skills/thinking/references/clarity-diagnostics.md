# 清晰度诊断协议

复杂想法很少只是“表达不好”。通常是概念、层级、因果或决策结构本身尚未分开。先用 [cognitive-router.md](cognitive-router.md) 确定主要卡点和本轮认知动作，再从这里选择最影响当前结论的 1–3 项诊断；不要把整张清单倒给用户。

## 诊断类型

| 类型 | 典型信号 | 要做的认知工作 |
|---|---|---|
| 问题未提炼 | 只讲了一个大主题或很多做法，却看不出想得到什么、被什么卡住 | 写成“目标—阻力—后果”，再区分症状与根因 |
| 概念含混 | 同一个词前后含义变化；两个近义词被当成同一事物 | 给出用法差异和候选定义，用具体例子检验 |
| 类别或层级混合 | 原则、系统、项目、策略、任务混在一个平面 | 重建上下层关系，指出哪个决定哪个 |
| 因果跳跃 | 从 A 直接跳到 B，没有机制、条件或中介变量 | 补出候选因果链，并标明缺证据处 |
| 隐藏前提 | 结论只有在某个没说出的假设下才成立 | 把前提显性化，检查它是否真实且必要 |
| 内在矛盾或张力 | 两个主张表面冲突，用户又都想保留 | 判断是条件不同、时间尺度不同，还是必须取舍 |
| 决策依据缺失 | 有很多可做事项，却没有优先级来源 | 区分目标、约束、评价标准与机会成本 |
| 系统边界缺失 | 只看到局部动作，看不到输入、输出、反馈和外部约束 | 画出系统边界与反馈回路 |
| 未知变量 | 用户只在既有选项里打转，遗漏激励、资源、时间、主体或反馈 | 主动提出少量可能改变结论的变量 |
| 行动断裂 | 观点听起来正确，却无法改变下一次行为 | 找触发信号、决策规则、最小实验或检查点 |

## 四种常用重构

### 问题句

适合材料很多，但用户真正的矛盾还没被说出来：

`我想 {结果}，但 {阻力/旧做法} 正在导致 {在意的后果}`

写完后用第一性原理检查：目标是否真实、约束是否不可绕过、阻力是根因还是症状、删掉哪些惯例仍能达成结果。不要把“关于 X 的思考”当成问题提炼。

### 层级图

适合“很多事情都重要，但不知道它们是什么关系”：

`价值/目的 → 原则 → 系统/项目 → 策略 → 日常行动`

不要强套此模板；按用户材料增删层级。

### 因果链

适合“我觉得 A 会带来 B，但说不清为什么”：

`输入 → 转化机制 → 中间结果 → 反馈 → 最终结果`

把没有证据的箭头标为假设，不要用流畅语言掩盖缺口。

### 反馈回路

适合持续创作、学习、产品与商业系统：

`行动 → 外部反馈 → 新信息/素材 → 调整 → 下一轮行动`

检查回路是否真的闭合，以及反馈是否能回到决策层。

### 张力拆分

适合两个观点都部分成立：

- 各自在什么情境、阶段或时间尺度成立？
- 它们是互补、先后关系，还是资源上的真实冲突？

## 未知未知扫描

当用户可能“还不知道自己不知道什么”时，主动扫描：

- 是否遗漏关键主体及其激励？
- 是否只看一阶结果，忽略二阶后果？
- 是否只看短期，忽略长期积累或路径依赖？
- 是否忽略稀缺资源、硬约束与机会成本？
- 是否缺少外部反馈，导致整个结构只能自我循环？
- 是否把一种成功案例误当成普遍规律？

只提出最可能改变结论的候选变量，并说明它为什么重要。

## 推荐输出顺序

1. **当前清晰理解**：把用户原料重构成一版可判断的意思。
2. **核心问题与本质**：说清用户想得到什么、被什么卡住，以及最短因果解释。
3. **关键诊断**：指出最影响清晰度的 1–3 个问题。
4. **候选修复**：给出定义、层级、因果链或遗漏变量。
5. **必要问题**：只有答案会改变整体结构时才问一个。
