# 用户共鸣选题协议

目标是把用户已经想清楚的个人认识，翻译成目标读者正在经历、愿意点开了解的问题。选题分析是知识卡与用户之间的桥，不是用传播套路改写知识卡核心。

## 一、底层方法

借鉴咪蒙公开方法论中可复用的部分：寻找自我表达与用户需求的交集；围绕同一个想法生成多个角度，淘汰第一反应式的普通说法；优先选择“意料之外、情理之中”的真实反差；通过采访、互动和发布反馈验证，而不是把“我觉得”当成用户洞察。

只借鉴用户洞察、角度生成和反馈验证，不模仿煽动愤怒、制造群体对立或夸大承诺的表达风格。原始经历、结论强度和证据边界必须保持不变。

## 二、先分析，再得出选题

先在内部完成下面的分析，不把过程写进卡片：

1. **锁定自我表达**：这张卡真正想说什么，最有证据的判断是什么；选题不能为了传播改变它。
2. **确定具体用户**：这个判断与谁有关，他在什么场景里卡住，正在承受什么损失、担心或冲突。
3. **区分已知与未知**：用户已经知道什么、仍想知道什么、真正有情绪或疑问的点是什么。没有采访、留言或真实反馈时，把这些当作待验证假设，不能冒充用户洞察。
4. **生成多个角度**：围绕同一主张内部生成足够多的不同入口，主动淘汰第一反应、空泛主题和所有人都能想到的普通说法；不要看到一个用户问题就立刻改写成标题。
5. **寻找真实反差**：用户原来以为什么，卡片提供了什么不同判断；优先“意料之外、情理之中”，没有反差时不要硬造冲突。
6. **限定一个目标**：每个候选只完成一个任务——提供新角度、说清一个误判、解决一个具体问题或展示一种真实证明，不能把整张卡的所有价值塞进一个选题。
7. **筛选并标题化呈现**：按用户相关性、角度新鲜度、正文可兑现性和证据边界筛出 3–5 个候选，再用标题形式呈现，方便用户比较。

可用内部公式检查：

> 候选选题 = 自我表达与用户需求的交集 + 具体矛盾或代价 + 一个可兑现的新判断

参考笔记、模板和评测样例只能帮助理解结构。禁止复用其中的解释性标题、用户问题或候选选题；每一行都必须从当前知识卡及当前受众分析重新推导。

## 三、默认呈现

核心卡片之后只追加下面这段：

```markdown
## 选题建议

**目标读者**：{一句话写清具体人群与当前处境；若为推断，写“候选目标读者”}

| 用户可能关心的问题 | 候选选题（以标题方式呈现） |
| --- | --- |
| {用户会亲口问的具体问题} | **{候选选题}** |
| {问题 2} | **{候选选题 2}** |
| {问题 3} | **{候选选题 3}** |
```

默认 3–5 行，最强、最贴近卡片核心的候选放在前面。用户需要自己比较时，不替他强行选定唯一答案；用户明确要求推荐时，再标出首选并用一句话说明理由。

## 四、两列怎样分工

### 用户可能关心的问题

- 使用第一人称或用户日常会说的话。
- 写具体目标、阻力或损失，不写“如何提升认知”“如何建立系统”等空主题。
- 每行代表一个不同的用户入口，不把同一个问题换词重复。
- 用户没有提供受众证据时，只能写“可能关心”，不能宣称已经验证。

### 候选选题（以标题方式呈现）

- 选题不等于最终标题；这里用标题形式呈现，是为了快速比较。
- 必须先完成上面的选题分析与筛选，不能把左列问题直接改写成一句更刺激的话。
- 可以使用问题、反差、代价、误判或具体结果增强张力。
- 只增强表达张力，不增强事实确定性。
- 必须由知识卡的真实经历、逻辑和边界完整兑现。
- 不使用虚构数字、虚假普遍性、羞辱、恐吓或人为制造的群体对立。

## 五、简洁约束

默认不要加入：

- 每条选题的“给谁、共鸣点、内容承诺、传播评分”等重复字段；
- 一段解释如何提炼选题的方法；
- 10 个以上标题或一组只有措辞差异的标题；
- 与“一句话、问题、解决方案、逻辑”重复的选题护城河说明。

只有用户明确要求深度选题分析时，才在对话中展开目标读者、验证证据、渠道和标题测试；不要把这些塞回知识卡。

## 六、检查

- 左列是否像目标读者会说的话，而不是创作者的行业术语？
- 右列是否经过用户、角度、反差、单一目标和证据筛选，而不是把左列简单改成标题？
- 候选是否来自当前卡片，而不是复用了模板、参考笔记或评测样例里的文案？
- 不看原对话，能否一眼比较候选之间的不同入口？
- 每个候选能否由卡片正文兑现？
- 删除任何一行后，是否确实少了一个不同的用户入口？
