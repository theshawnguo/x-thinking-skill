# 费曼式卡片表达协议

目标不是把话说得幼稚，而是让用户**一次读懂，还能用自己的话讲出来**。

## 一、先确定读者关心什么

写每句话前先回答：

1. 用户此刻想做到什么；
2. 什么正在让他难受、浪费时间或拿不到结果；
3. 这句话会帮助他看懂什么，或下一步做什么。

如果一句话只是在展示概念、补背景或显得完整，却不帮助理解和行动，删除它。

## 二、四步改写

1. **说具体**：把“系统、价值、主轴、沉淀、赋能、闭环”等抽象词换成看得见的场景、动作和结果。
2. **拆长句**：一句只说一个主要关系；三个以上并列成分通常需要删减或拆开。
3. **讲因果**：不要只宣布结论，要用最短路径说明“因为发生了什么，所以结果怎样”。
4. **换位复述**：假设在向一个聪明但不了解背景的朋友解释；他能否不看原文复述出同一个意思？

## 三、信息密度

高信息密度不是名词多，而是每句话都在完成至少一项工作：

- 说清用户的真实矛盾；
- 区分表面问题和真正原因；
- 解释一个必要的因果关系；
- 给出可以执行或检验的动作。

同一句若只换词重复前文，不算新信息。陌生概念若需要额外解释、又不能明显提高准确度，反而降低信息密度。

## 四、抽象词替换示例

不要机械禁用抽象词；先问能否换成更快理解的说法：

- “以真实事业和项目为生活主轴” → “先把真正想做成的项目往前推”。
- “让行动产生问题与经验” → “做的过程中遇到什么、怎么解决，就把它记下来”。
- “将经验沉淀为内容资产” → “把已经做过、想清楚的事写成别人用得上的内容”。
- “建立反馈闭环” → “发出去，看别人哪里有反应，再决定下一次改什么”。

## 五、禁止的偷懒写法

- 把多个正确概念串成一句很长的话。
- 用“本质上、核心是、底层逻辑”替代真正的解释。
- 为了显得专业，把用户熟悉的动作改写成行业术语。
- 把“口语化”误解成加语气词、网络词或刻意模仿用户口头禅。
- 用更多例子掩盖核心问题还没有被说清。

## 六、发送前测试

- 句子里是否有必须二次翻译的词？
- 用户能否一眼看见“这和我有什么关系”？
- 用户能否用自己的话复述，而不是只能照念？
- 删除任何一句后，是否会损失新的理解或行动信息？如果不会，就删除。
- 脱离原对话后，“一句话—问题—解决方案—逻辑”能否直接讲成一段口播或扩写成文章？
- “逻辑”是否每一点都增加新信息，而不是复述前面的字段？
