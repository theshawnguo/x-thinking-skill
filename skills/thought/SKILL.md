# thought — 消化过去的碎片

`/thinking` 处理当下一个想法；`/thought` 处理过去积累的一批碎片。两者共用同一个**共同思考引擎**：主动重构、诊断、补充、检验，而不是只靠提问让用户自己整理。

开始前完整读取并遵循 [../thinking/SKILL.md](../thinking/SKILL.md)。理论依据见 [../thinking/PRINCIPLES.md](../thinking/PRINCIPLES.md)。本文件只规定批量材料的前置消化。

## 前置流程：取 → 聚 → 纵 → 诊 → 选

### ① 取：只读获取碎片

- 接受粘贴文本、一个或多个 `.md` 文件、文件夹路径。
- 路径输入只读扫描；绝不修改、移动或删除旧笔记。
- 记录时间、来源等已有元数据，跨时间变化可能比关键词更重要。

### ② 聚：按问题与意图聚类

- 不只按关键词；判断每条碎片试图理解什么、解决什么或决定什么。
- 合并“同一个问题在不同时间的不同说法”。
- 保留孤立但可能关键的异常笔记，不为聚类整齐而硬塞。

### ③ 纵：看见跨时间变化

主动找出：

- 反复出现但一直没有收敛的问题；
- 早期与后期观点的变化；
- 表面矛盾背后的情境、阶段或价值冲突；
- 已经出现多次、可能支持候选原则的经验模式。

“反复出现”只代表重要或未解决，不自动代表正确。

### ④ 诊：交付全景而非只问问题

首轮先给用户：

1. 主题簇及每簇真正关心的问题；
2. 跨时间的重复、变化与矛盾；
3. 最值得深入的 1–3 个候选及理由；
4. 你看到的概念混用、逻辑缺口或遗漏变量。

遵循 thinking 的来源标注与问题预算。禁止只列完主题后问“你想选哪个”。

### ⑤ 选：聚焦一个原子问题

- 若优先级明显，主动推荐一个并说明理由，再让用户确认或改选。
- 若多个候选同等重要，最多问一个选择问题。
- 选定后进入 thinking 的“架 → 诊 → 补 → 辩 → 炼 → 迁 → 卡”。碎片已经完成“收”，不要重复采访用户已经写过的内容。

## 成卡规则

- 一次通常深入一个原子问题、生成一张主卡；其他主题保留为后续候选。
- 跨时间材料可以提高证据强度，但仍要检查适用情境、机制、反例和成熟度。
- 卡片 frontmatter 使用 `source: thought`。
- 配置、卡片、关联和中途退出规则全部继承 thinking。
